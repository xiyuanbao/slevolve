    Code structure¶

    This page describes how the release sources are organised and how one time step is carried out in the code. Routine and class names are given with the file that contains them. The code excerpts are copied from the release sources. ... marks lines left out between complete statements.

    Python imports. The modules of python/slevolve/ import each other relatively (from .solver import ..., from .. import npyio in slevolve.tools), so the same files work installed (pip install .) and from a checkout. The scripts python/run_ais.py, python/run_outer.py, python/init_topo_segmented.py and python/tools/<name>.py put python/ on sys.path and call main() of the package module, so the documented commands are unchanged. Code outside the package (tests, examples, tools/) imports from the package: from slevolve.solver import LoveNumbers, from slevolve.tools.plot_fields import mollweide_map, after sys.path.insert(0, "python") in a checkout or with no path change when the package is installed. run_ais and run_outer parse their arguments and pin the thread counts at import, before NumPy is imported; import slevolve itself does not import NumPy.

    2. Fortran architecture¶

    2.1 Modules and build order¶

    build.sh compiles, in this order: the generated support module, npy_io_mod.f90, io_mod.f90, spharmt_otf.f90 (as spharmt.o), modal_state_mod.f90, sl_model_mod.f90 and the selected driver. The use relations are:

    driver (run_from_zero_plus | run_outer_plus | run_outer_mem)
 |-- sl_model_mod                      sl_model_mod.f90
 |    |-- spharmt                      spharmt_otf.f90 (+ otf_kernels.inc with SHT=otf)
 |    |-- user_specs_mod               generated support module
 |    |-- planets_mod                  generated support module
 |    |    `-- constants_mod
 |    |-- sl_io_mod                    generated support module (legacy text read_sl / write_sl)
 |    |    `-- user_specs_mod
 |    |-- modal_state_mod              modal_state_mod.f90
 |    `-- io_mod                       io_mod.f90
 |         `-- npy_io_mod              npy_io_mod.f90
 |-- spharmt                           (sht_profile counters)
 |-- user_specs_mod                    (dt1; outer drivers)
 `-- io_mod                            (pp_read_options, pp_shtprof)

    Compile-time parameters (step length dt1, number of steps L_sim, truncation norder, tolerance epsilon1, file names, tpw, checkmarine, initial_topo, constants) live in user_specs_mod and are set by build.sh. Run-time switches are environment variables read by io_mod::pp_read_options (with inner_read_options and opt_read_options) and by spharmt::sht_env_init (SLEVOLVE_FFT); see Command-line options.

    2.2 Drivers¶

    All three drivers call the same solver routines:

    1. sl_solver_checkpoint(itersl, dtime): checks dtime == dt1, sets the planet (set_planet), reads the run-time options, initialises the transform backend (sht_env_init, spharmt_init).
    2. Step 0: sl_timewindow(0), sl_allocate_and_initialize_array, sl_solver_init(itersl, 0.0), sl_deallocate_array.
    3. Steps iter = 1..LAST: sl_timewindow(iter), sl_allocate_and_initialize_array, sl_solver(itersl, iter, dtime, 0.0), sl_deallocate_array.
    4. sl_print_counts.
    driver command what differs
    run_from_zero_plus.f90 ./exe LAST forward run; itersl = 1, step length dt1 = build-time DT (or the times file); optional transform profile print (SLEVOLVE_SHTPROF)
    run_outer_plus.f90 ./exe LAST [ITERSL] one outer pass; dtime = dt1; pass ITERSL > 1 reads pred_pres_topo_<k-1> and tgrid0_<k-1> from OUTPUT_SLM/ in sl_solver_init
    run_outer_mem.f90 ./exe LAST K0 K1 passes K0..K1 in one process; sets pp_mem_outer, reads SLEVOLVE_ICECACHE; calls sl_outer_reset between passes; copies OUTPUT_SLM/numiter to numiter_<k> and prints the wall time per pass

    The outer update of the initial topography is done in sl_solver_init at the start of pass itersl > 1 (Picard update, or outer_secant with SLEVOLVE_OUTER=secant). At the last step, sl_solver writes pred_pres_topo_<itersl> and tgrid0_<itersl> (and with run_outer_mem also keeps them in memory for the next pass).

    2.3 One time step (sl_model_mod::sl_solver)¶

    1. Setup and ice. opt_setup; the ice grid of the current step is read with pp_ice_get (at iter == 1 also the time-zero grid). pp_ice_get serves the grid from the in-memory ice cache (run_outer_mem) or through pp_read_grid (.npy, then .bin, then text). The physical times of the previous and current step are appended to the time array file.
    2. Step-0 fields. tinit_0, cxy0, beta0 stay resident (re-read only with SLEVOLVE_COMPAT bit 1); the previous step's ocean function is already in cxy.
    3. Earth model (once per run). The Love-number file is parsed in the block "Read in Love numbers", guarded by pp_love_ready; the response spectrum exact_spec (decay rates and the weights a_sl, a_rr, degree-2 a_il, a_m, a_tsl, a_trr, and a_hl, a_thl when SLEVOLVE_HORIZ > 0) is built from it, and exact_state%init allocates the modal state.
    4. Advance-and-read. At iter == 1 the state is zeroed (exact_state%zero); otherwise it is resident (or reloaded with load_checkpoint under SLEVOLVE_COMPAT bit 4). Then exact_state%advance_and_read advances every modal state by one decay factor and returns the viscous sea-level and radial sums and the degree-2 rotational sums. These are frozen for the whole inner iteration. The cumulative loads deltaS(:,:,exact_prev), oldil, oldm and the previous deltalambda are restored from p_ocean, p_il, p_m, p_lambda.
    5. Ice and ocean setup. Transform of the initial topography (once, pp_t0lm_ready), the grounded-ice and beta fields (STEP 3), the warm-start read warm_read (with SLEVOLVE_REUSE=warm; replaces the ocean mask), and the batched analyses (opt_ana_multi) of the ice, cstar and tO grids.
    6. Inner start. Eustatic first guess for the ocean-load increment load_inc_lm; with SLEVOLVE_INNER=extrap (or anderson) and two stored converged increments, the extrapolated start replaces it; with a warm-start record, the stored increment of the previous pass replaces both.
    7. Inner iteration (the do loop between "Start of inner loop" and "End of inner loop"): rotation (tpw: moment of inertia, m, lambda, using the frozen exact_sum_il, exact_sum_m, exact_tsl, exact_trr); sea-level change from the load (STEP 6, elastic part plus frozen viscous); synthesis; r0, conservation term and new ocean load (STEPS 7 to 9); convergence measure xi on sum(abs(load_inc_lm)); ocean-function update and re-analysis while xi > epsilon1; optional Anderson mixing (inner_anderson). The loop exits when xi <= epsilon1 and aborts at 9999 iterations.
    8. After convergence. The converged load_inc_lm and dtime are pushed into the extrapolation history (extrap_dsm1, extrap_dsm2, extrap_dtm1, extrap_dtm2); R and G are formed from the frozen exact_radial when they are written (lazyrg); the optional horizontal read-out (exact_state%read_horizontal, SLEVOLVE_HORIZ) is done on the same states.
    9. Commit. The current load rhoi*dicestar + rhow*load_inc_lm (degrees 1..norder) is added to p_load with exact_state%commit (with dil, dm, dlambda when tpw); the cumulative p_ice, p_ocean, prev_ice are stored; save_checkpoint only with SLEVOLVE_CKPT or SLEVOLVE_COMPAT bit 4.
    10. Topography and outputs. topoxy = tinit - deltaslxy, new ocean function cxy (STEP 11); warm_write (warm-start store); diagnostics (ocean areas, GMSL, ice volume); text scalars (numiter, nmelt, TPW<N>, ...); grids through pp_write_grid (tgrid, ocean, beta, R, G) and pp_write_cplx (dS_converged), subject to SLEVOLVE_SNAP; at the last step pred_pres_topo_<itersl> and tgrid0_<itersl>.

    3. Python architecture¶

    run_ais.py (forward)        run_outer.py (outer passes)       init_topo_segmented.py
      |                            |                                 |
      |  npyio (read_grid, IceDir, save_grid, save_spectral)        |  solver.LoveNumbers, Planet
      |  solver.LoveNumbers, Planet                                  |
      |  sht_ducc.make_sht -> sht.SHT | sht_ducc.DuccSHT            |
      v                            v
solver_opt.OptSeaLevelSolver  (subclass of solver.SeaLevelSolver, overrides step)
      |-- state: solver_opt.ExactMemoryFast (subclass of solver.ExactMemory)  [opt "numba"]
      |          or solver.ExactMemory
      |-- kernels (Numba kernels)                                            [opt "numba"]
      |-- solver_opt._Anderson                                               [--inner anderson]
      `-- horiz.gradient (grid components, called by the drivers)            [--horizontal-grid]
    • run_ais.py parses the options, builds the ice cache, reads the topography (read_grid_any) and the Love numbers (solver.LoveNumbers), creates the transform with sht_ducc.make_sht (--sht numpy|ducc), and uses OptSeaLevelSolver when --opt or --inner is given, otherwise the reference SeaLevelSolver (with dt = --dt, or the first step of --times). It then calls step(ice[k]) for k = 1..steps and writes tgrid<k>.npy, ocean, beta, R, G, dS_converged, horiz (--save-fields, --horizontal, --horizontal-grid), numiter.npy and run_log.json.
    • run_outer.py creates one OptSeaLevelSolver per outer pass (dt=--dt, default opt raw,diag,dsl,numba,sums, ducc0 transform), passes the dict store that survives across passes for --reuse warm, runs all steps, and updates the initial topography by Picard or per-cell secant (--outer). It writes pred_pres_topo_<it>.npy, tgrid0_<it>.npy, saved steps and T0_next.npy.
    • solver.SeaLevelSolver.__init__ does what sl_solver_init does (step 0: initial topography, ocean and beta functions, their spectra) and creates the state ExactMemory; OptSeaLevelSolver.__init__ replaces it by ExactMemoryFast when numba is selected.
    • OptSeaLevelSolver.step follows the same sequence as sl_solver: state.advance_and_read(), grounded ice I* on the previous converged topography, beta and ocean grids, ice analysis and increments, eustatic guess, extrapolated start (inner != "off"), warm start (reuse_store), inner loop (rotation, kernels.b18, synthesis, conservation, kernels.dS_update, convergence measure xi, ocean-function update or Anderson mixing), history push, R/G from radial, optional horizontal_lm, state.commit(...), topography and ocean function (kernels.topo_ocean), diagnostics. It returns a dict of fields (tgrid, ocean, beta, R, G, dS_converged, horiz, scalars).
    • parse_opts turns --opt (raw, diag, dsl, numba, sums, or all) into a set; each item switches one optimisation of step.
    • sht.SHT (NumPy/BLAS table) and sht_ducc.DuccSHT (ducc0) share analysis(grid, out) and synthesis(coeffs, out); make_sht(backend, ...) selects one. The raw option exists only for ducc0.
    • npyio holds the file conventions shared with the Fortran (read_grid tries .npy, .bin, text; IceDir reads <dir>/<pfx><k> on demand).
    • horiz.gradient(U, nlat, nlon) turns the spectral Psi_lm into (u_theta, u_phi) with the ducc0 spin-1 gradient synthesis.

    4. Code excerpts¶

    4.1 Modal-state advance and commit¶

    The advance loop of state_advance_and_read in fortran/src/modal_state_mod.f90 (the degree-2 rotational states follow after it):

    call update_decay(self,spec,dt_years)
viscous=(0.0_dp,0.0_dp); radial=(0.0_dp,0.0_dp)

! Packed layout is [degree][pole][m=0:l], so each pole update is one
! contiguous vector operation.  R itself is the hereditary response state:
! R_new = d*R_old + (1-d)*DL_old   (DL = cumulative load, p_load).
! degrees are independent (each writes a disjoint slice of
! r_load / viscous / radial and accumulates over kk in the same order),
! so this loop threads identically.
!$omp parallel do schedule(dynamic,4) default(shared) private(ll,kk,ibase,rstart,rend,d,omd)
do ll=1,self%lmax
   ibase=lm_index(ll,0)
   do kk=1,self%nmod(ll)
      d=self%decay(kk,ll); omd=1.0_dp-d
      rstart=int(self%roffset(ll))+(kk-1)*(ll+1)
      rend=rstart+ll
      self%r_load(rstart:rend)=d*self%r_load(rstart:rend) + &
                                omd*self%p_load(ibase:ibase+ll)
      viscous(ibase:ibase+ll)=viscous(ibase:ibase+ll) + &
                              spec%a_sl(kk,ll)*self%r_load(rstart:rend)
      radial(ibase:ibase+ll)=radial(ibase:ibase+ll) + &
                             spec%a_rr(kk,ll)*self%r_load(rstart:rend)
   end do
end do
!$omp end parallel do

    state_commit in the same file only adds the converged increments to the accumulated loads:

    subroutine state_commit(self,current_load,dil,dm,dlambda)
  class(response_memory_state), intent(inout) :: self
  complex(dp), intent(in) :: current_load(:)
  real(dp), intent(in), optional :: dil(3,3),dm(3)
  complex(dp), intent(in), optional :: dlambda(0:2)
  self%p_load=self%p_load+current_load
  if (present(dil)) self%p_il=self%p_il+dil
  if (present(dm)) self%p_m=self%p_m+dm
  if (present(dlambda)) self%p_lambda=self%p_lambda+dlambda
end subroutine state_commit

    The Python equivalent of the advance, the body of advance_and_read in python/slevolve/kernels.py (state stored as R[l, k, m], used by ExactMemoryFast):

    nl = R.shape[0]
for l in prange(nl):
    nk = nmod[l]
    for m in range(nl):
        visc[l, m] = 0.0
        rad[l, m] = 0.0
    for k in range(nk):
        d = decay[k, l]
        o = omd[k, l]
        s = a_sl[k, l]
        q = a_rr[k, l]
        for m in range(l + 1):
            x = R[l, k, m] * d + P[l, m] * o
            R[l, k, m] = x
            visc[l, m] += x * s
            rad[l, m] += x * q

    Here P (p_load in both codes) holds the cumulative load ΔL(t_{j-1}).

    and ExactMemory.commit in python/slevolve/solver.py:

    def commit(self, current_load, dil=None, dm=None, dlambda=None):
    self.p_load += current_load
    if dil is not None:
        self.p_il += dil
    if dm is not None:
        self.p_m += dm
    if dlambda is not None:
        self.p_lambda += dlambda

    (shown without the branch of the optional second-order placement: with ramp on, the commit first adds \((1-\varphi_k)\) times the increment to every state, ExactMemory._ramp_commit_load and kernels.py::ramp_commit in Python, state_ramp_commit in Fortran; see Method).

    4.2 Placement of advance and commit in the time step¶

    In sl_solver (fortran/src/sl_model_mod.f90) the state is advanced and read once before the inner iteration and committed once after convergence; the inner iteration and the R, G and horizontal read-outs lie between the two parts (left out):

    ! the 53 MB hereditary state stays in memory across timesteps;
! the baseline writes and reads it back on every single step.
if (iter == 1) then
   call exact_state%zero()
   pp_state_ready = .true.
else if (.not. pp_state_ready .or. iand(pp_compat,4) /= 0) then
   call exact_state%load_checkpoint(trim(exact_statefile),exact_spec)
   pp_state_ready = .true.
endif
call exact_state%advance_and_read(exact_spec,real(dtime,dp),exact_viscous,exact_radial, &
                                  exact_sum_il,exact_sum_m,exact_tsl,exact_trr)
...
! Commit the converged current-step increments only now.  The current
! load has zero age at this instant, so it did not contribute to the
! hereditary response used above; it becomes memory for future steps.
exact_current_load = (0.0_dp,0.0_dp)
!$omp parallel do schedule(static) default(shared) private(l,m,exact_idx)
do l = 1,norder
   do m = 0,l
      exact_idx = lm_index(l,m)
      exact_current_load(exact_idx) = rhoi*dicestar(l,m,exact_cur) + rhow*load_inc_lm(l,m)
   enddo
enddo
!$omp end parallel do
if (tpw) then
   call exact_state%commit(exact_current_load,dil(:,:,exact_cur),dm(:,exact_cur),dlambda(2,0:2,exact_cur))
else
   call exact_state%commit(exact_current_load)
endif

    np.multiply(self.load_inc_lm, p.rhow, out=self._sp2)
    self.current_load += self._sp2
    self.current_load[0, :] = 0.0
if self.tpw:
    self.state.commit(self.current_load, dil_cur, dm_cur, dlam_cur2)
else:
    self.state.commit(self.current_load)

    4.3 Extrapolated inner start¶

    The coefficients are computed by extrap_coeffs in fortran/src/modal_state_mod.f90; for equal steps they are exactly 2 and -1:

    ! Coefficients of the extrapolated inner start (variable steps):
!   dS0_j = dt_j [ Sdot_{j-1} + (Sdot_{j-1} - Sdot_{j-2}) (dt_j + dt_{j-1}) / (dt_{j-1} + dt_{j-2}) ],
!   Sdot_i = dS_i / dt_i,   i.e.  dS0_j = c1 dS_{j-1} + c2 dS_{j-2};
! equal steps give exactly c1 = 2, c2 = -1.  dt0 = dt_j, dtm1 = dt_{j-1}, dtm2 = dt_{j-2}.
pure subroutine extrap_coeffs(dt0, dtm1, dtm2, c1, c2)
  real(dp), intent(in) :: dt0, dtm1, dtm2
  real(dp), intent(out) :: c1, c2
  if (dt0 == dtm1 .and. dtm1 == dtm2) then
     c1 = 2.0_dp; c2 = -1.0_dp
  else
     c1 = dt0 / dtm1 * (1.0_dp + (dt0 + dtm1) / (dtm1 + dtm2))
     c2 = -dt0 / dtm2 * ((dt0 + dtm1) / (dtm1 + dtm2))
  endif
end subroutine extrap_coeffs

    and applied in sl_solver (fortran/src/sl_model_mod.f90), where dtr is the length of the current step (from the times file, else the build-time DT):

    ! extrap: linear-in-time extrapolation of the converged
! increment; the cumulative current load that the first rotation
! evaluation reads is made consistent with it.  For uniform steps this
! is 2 dS(n-1) - dS(n-2); for variable steps the rate dS/dt is
! extrapolated linearly between step midpoints and scaled by dt(n).
if (inner_mode > 0) then
   if (.not. allocated(extrap_dsm1)) then
      allocate(extrap_dsm1(0:norder,0:norder), extrap_dsm2(0:norder,0:norder))
      extrap_dsm1 = (0.0,0.0); extrap_dsm2 = (0.0,0.0)
   endif
   if (inner_nhist >= 2) then
      ! paper Sect. 2.5: dS0_j = c1 dS_{j-1} + c2 dS_{j-2} (modal_state_mod::extrap_coeffs)
      call extrap_coeffs(dtr, extrap_dtm1, extrap_dtm2, extrap_c1, extrap_c2)
      !$omp parallel do schedule(static) default(shared) private(m)
      do m = 0,norder
         load_inc_lm(:,m) = extrap_c1 * extrap_dsm1(:,m) + extrap_c2 * extrap_dsm2(:,m)
         deltaS(:,m,exact_cur) = deltaS(:,m,exact_prev) + load_inc_lm(:,m)
      enddo
      !$omp end parallel do
   endif
   inner_nh = 0; inner_lastmixed = .false.; inner_plain_rest = .false.; inner_nrefreeze = 0

    The Python version is extrap_guess in python/slevolve/solver_opt.py:

    def extrap_guess(h1, h2, dt0, dt1, dt2, out=None):
    """Extrapolated inner start of step j (paper Sect. 2.5):

        dS0_j = dt_j [ Sdot_{j-1} + (Sdot_{j-1} - Sdot_{j-2}) (dt_j + dt_{j-1}) / (dt_{j-1} + dt_{j-2}) ],
        Sdot_i = dS_i / dt_i,

    with h1 = dS_{j-1}, h2 = dS_{j-2}, dt0 = dt_j, dt1 = dt_{j-1}, dt2 = dt_{j-2}.  Equal steps give
    exactly 2 dS_{j-1} - dS_{j-2}."""
    if out is None:
        out = np.empty_like(h1)
    if dt0 == dt1 == dt2:
        np.multiply(h1, 2.0, out=out)
        out -= h2
    else:
        w = (dt0 + dt1) / (dt1 + dt2)
        np.multiply(h1, dt0 / dt1 * (1.0 + w), out=out)
        out -= (dt0 / dt2 * w) * h2
    return out

    called in OptSeaLevelSolver.step with the lengths of the current and the two previous steps:

    if acc and self._dS_nhist >= 2:
    h1, h2 = self._dS_hist  # dS_{n-1}, dS_{n-2}
    # linear-in-time extrapolation of the increment: for uniform steps
    # 2 dS_{n-1} - dS_{n-2}; for variable steps the rate dS/dt is
    # extrapolated between step midpoints and scaled by dt_n
    extrap_guess(h1, h2, float(self.dt), self._dt_hist[0], self._dt_hist[1],
                 out=self.load_inc_lm)
    # the rotation block of iteration 1 reads deltaS_cur: give it the
    # same guess (plain iteration 1 reads 0 here)
    np.add(deltaS_prev, self.load_inc_lm, out=self.deltaS_cur)

    4.5 Horizontal-displacement read-out¶

    In sl_solver (fortran/src/sl_model_mod.f90), between the inner iteration and the commit: the modal states are read with the l weights and combined with the elastic l number and the degree-2 rotational term:

    call exact_state%read_horizontal(exact_spec, exact_horiz, exact_thl)

if (nmelt /= 0) then
   !$omp parallel do schedule(static) default(shared) private(l,m,ttl,exact_idx)
   do l = 1,norder
      ttl = (4.0 * pi * (radius**3)) / (mass * (2.0 * real(l) + 1.0)) ! (eq. B16)
      do m = 0,l
         exact_idx = lm_index(l,m)
         hzlm(l,m) = ttl * (elast(2,l)/real(l)) * (rhoi * deltaicestar(l,m,exact_cur) &
                  & + rhow * deltaS(l,m,exact_prev) + rhow * load_inc_lm(l,m)) &
                  & + ttl * exact_horiz(exact_idx)
      enddo
   enddo
   !$omp end parallel do
   if (tpw .and. norder >= 2) then
      do m = 0,2
         hzlm(2,m) = hzlm(2,m) + ((telast(2,2)/2.0) * (deltalambda(2,m,exact_prev) &
                  & + dlambda(2,m,exact_cur)) + exact_thl(m)) / gacc
      enddo
   endif
endif
